# CI notes for the GPUI shell migration

## Workflows

- `rust.yml`: the Rust workspace at `app/Cargo.toml` plus Swift lint. Jobs: `rust-lint` (rules script, fmt, clippy, rustdoc, cargo-deny, cargo-machete; Linux), `rust-test` (clippy, headless tests, GUI tests; Linux and macOS arm64), `rust-build` (release binary of `app/desktop/app`, uploaded as an artifact, unsigned), `swift-lint` (macOS), `rust-ok` (aggregate).
- `ci.yml`: Go, web (`app/panes`), website, mobile crate (`app/mobile/src-tauri`, separate workspace), iOS. `ci-ok` is its aggregate.
- Required status checks: require `ci-ok` and `rust-ok` only. Both pass when their jobs are skipped by path filters, so a PR touching neither area is never stuck pending. Before this change no aggregate existed; branch protection must be updated by a repo admin.
- GUI tests are `#[ignore = "needs display"]` and run in a second `cargo test -- --ignored` step (Xvfb, openbox, lavapipe on Linux). The macOS GUI step is non-blocking until the first runs show it is stable.
- `app/Cargo.lock` must be committed: every cargo step uses `--locked` and the cache keys on it.

## Not yet covered

- Intel macOS: only a `cargo check --target x86_64-apple-darwin` from the arm64 runner. A native Intel runner is deferred until the release pipeline needs it.
- The release workflows (`prerelease.yml`, `stable-release.yml`, `nightly.yml`) still build the old Tauri desktop app from the Go daemon and web bundle. They are untouched.
- The GPUI release pipeline (code signing, notarization, updater feed, Linux packaging) is a later task. `rust-build` artifacts are unsigned CI builds, not release candidates.
